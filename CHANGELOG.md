# Changelog

All notable changes to RedMan.

Versioning scheme:
- **X.X.1** - Patches: bug fixes, small UI improvements, and documentation changes
- **X.1.X** - Minor: new features, new workflows, and new settings
- **1.X.X** - Major: breaking data-model or deployment changes

### Added
- [x] Added a **Dry Run** action to every Media Import source. It runs Immich's own simulation against the same remaining work and reports what would be scanned, uploaded, skipped, or rejected without changing Immich, import checkpoints, source files, drive state, or `last_import_at`; only run and report metadata is recorded. Online Takeouts skip existing checkpoints, download each remaining archive for analysis, then remove only the temporary staging copies created by the simulation. Dry runs remain labelled in live progress, history, and run details.
- [x] Added reliable **Media Import cancellation across the complete job lifecycle**. The existing Cancel action now stops remote archive discovery, downloads, Immich analysis, and the orchestration gaps between them instead of failing with “process not found” whenever no child process happened to be active.
- [x] Extended the integrated **atomic progress pattern to every job view**. SSD Backup shows Prepare, Transfer, and Finalize; Hyper Backup shows Connect, Transfer, and Confirm; Cloud Backup shows Check, Transfer, and Finalize; regular Media Import shows Scan, Upload, and Finish. Each uses the same inline progress bar and feature-specific live metrics without a card inside the existing job card.
- [x] Running backup jobs now replace their historical health summary in-place with live progress. Last success, last issue, verified restore, and next run return when the job finishes, keeping each card focused on what matters now without making it taller during a run.
- [x] Added a short **Starting job transition** between the scheduled health view and live backend progress. Three staged nodes and a moving rail show that the run was accepted while RedMan waits for its first real progress update; the actual stepper then enters in place, with motion disabled automatically for reduced-motion preferences.
- [x] Atomic progress steps now animate their state changes: the connector fills toward the next stage, the active node enters with a restrained ring, and completion resolves into a drawn check. Reduced-motion users receive the same state changes instantly.
- [x] Sequenced stage transitions so the completed connector resolves green before the next connector advances blue, making the direction of progress readable instead of animating both segments at once.
- [x] Added an **atomic step progress view** for online Takeout imports: Scan, Download, Import, and Cleanup show as compact states around one real overall progress bar. Live inline metrics count scanned assets, new uploads, assets already present in Immich, and errors, so a large mostly-duplicate import visibly advances instead of appearing frozen between archives. The progress controls are integrated into the source card rather than presented as a nested card.
- [x] Added a fully managed **online Google Photos import** to Media Import. After choosing a connected Google Drive remote, RedMan finds the Takeout folder and starts automatically. It processes one `.zip`, `.tgz`, or `.tar.gz` archive at a time: checking disk space, downloading, importing into Immich, checkpointing success, deleting only the local staging copy, and moving to the next. Staging stays private inside RedMan's persistent data mount rather than the Docker image, while the Takeout path remains available under Advanced options. A failed archive stays staged for a resumable retry, while the Google Drive source is never deleted.
- [x] Added **retries to Hyper Backup's peer calls**, so a night's backup is no longer lost to a connection that timed out for fifteen seconds. Only failures that mean *ask again later* are retried — a timeout, a reset, a refused connection, a gateway that is restarting — because nothing was answered and so nothing was decided. Failures that are a decision are never retried: an exceeded quota, a destination refused as unsafe, and a rejected key give the same answer however often they are asked, and asking again only wastes the peer's time and buries the reason. Each wait is three times the last, so a struggling peer is not stampeded. A retry that worked is still recorded, because silently recovering is how a degrading link stays invisible until the night it does not recover.
- [x] Added `--wait-for-idle` to deployment, so a deploy that arrives while a backup is running can wait for it instead of choosing between giving up and interrupting it. Until now the only way past the activity check was `--force`, which stops the running job — the right tool when a deploy cannot wait, and the wrong one when it can. The wait never signals a job; it asks again until the job ends on its own or the budget runs out, so the worst outcome is a deploy that did not happen.
- [x] Added a **disk health check on the destination a backup is written to**, so a Hyper Backup job can tell you whether the copy it is about to make will survive. Disk health alone does not answer that: the same failing drive is survivable under a mirror and is data loss without one, so the verdict combines what the drives report with how the pool is laid out. On Unraid a destination is written as a share, which is a union rather than a pool, so the share table is resolved too — and a share that nothing pins is a warning on its own, because new data can land somewhere with less protection than the disks that were measured.
- [x] Added a **refusal to push onto a destination known to be dying**. Not to spare the disk the writes: a push overwrites what is already there, so accepting one onto a failing destination trades the copy that still works for one that may not survive. The peer decides, exactly as it already does for its storage quota, and refuses on the same terms — on evidence, never on its absence. An instance without the collector, a path that traces to no pool, and a peer that cannot measure all keep working exactly as before, because losing a night's backup over a missing measurement is the more expensive failure by far. Enforcement can be turned down to a warning.
- [x] Added **Storage** and **Backup destinations** to the status board, and the destination's verdict to each Hyper Backup job. RedMan cannot read SMART from inside its own container without privileges that would cost more than the answer is worth, so a small collector on the host measures instead and RedMan reads what it wrote. A sleeping disk keeps its previous reading rather than being woken, and a disk whose health cannot be read is reported as unknown or unsupported — never as healthy.
- [x] Added **browsing to the Remote Path** of a cloud backup job. The field was free text, so the path was typed from memory and a typo only surfaced when the first run failed — and against a provider like Google Drive, where the folder name is whatever the export happened to call it, that guess is hard to make correctly. The remote can now be opened and navigated, so you pick a folder that demonstrably exists. It opens where the field already points rather than at the top of the drive, and a path that cannot be opened says so and drops you at the root instead of leaving a dead end. Browsing is also the first honest test of the connection: a remote whose authorisation has lapsed fails here, while you are still filling in the form, instead of at three in the morning.
- [x] Added **folder import sources**, so photos already sitting on the machine can be imported into Immich without pretending to be a camera. Media Import only ever knew about removable media: the source had to be something the drive monitor had watched appear, which left a downloaded archive or a staging share with no way in at all. A folder inside RedMan's storage roots can now be declared as a source and imported on demand, with the same progress, cancellation, per-file report, and run history as a drive. Post-import source deletion and drive ejection stay switched off for one, because both describe hardware someone is waiting to unplug rather than a folder that is meant to stay where it is.
- [x] Added a **Google Photos takeout** mode to those sources, because reading a takeout as an ordinary folder quietly loses most of what makes it worth moving. Google exports a photo's date, location, and album membership into a JSON file beside it rather than into the file itself, so a plain upload arrives as an undated, unplaced, unsorted pile — recoverable only by doing the whole transfer again. A folder marked as a takeout is handed to immich-go as the archives themselves, read without unpacking, so the sidecars are matched and that metadata survives. The archives are passed in numeric order, since matching runs across archive boundaries, and a photo whose sidecar is missing falls back to its own EXIF data instead of being skipped in silence. The retry pass that re-uploads individual failed files is skipped in this mode, because a file inside an archive has no path on disk to link to.
- [x] Added a **folder-level test restore**, because recovering one file proves the mechanism while a backup's actual promise is the dataset. Any folder in a snapshot can now be restored into a destination of your choosing as a tracked background job — progress, cancellation, and run history like any other — walking the snapshot recursively, reconstructing deltas, and verifying every file with SHA-256. It checks there is room before it starts, rather than discovering it halfway through, and writes one audit row for the drill instead of one per file, since a folder can hold millions. The destination must sit inside the storage roots RedMan may already write to, may not overlap the backup destination, and may not be the backup source: a drill that overwrites live data is not a drill.
- [x] Added a **restore drill**: any revision can now be restored into a folder of your choosing instead of back over the original. Verifying a backup previously meant overwriting the live file to prove the copy was good, which is a destructive act nobody wants to rehearse — so the recovery path stayed untested, and "we have backups" remained a claim rather than a fact. A drill runs exactly the same code as a real restore, including delta reconstruction and the SHA-256 comparison, and records the same audited outcome; only the destination differs. The chosen folder must sit inside the storage roots RedMan is already allowed to write to and may not overlap the backup destination, because restoring into the snapshot store would corrupt the very history being recovered from.
- [x] Added a **diagnosis to failed Rclone runs**, so a run report says what actually broke instead of *146 file(s) failed*. Failures are grouped by cause rather than counted, and each cause is named in plain language with what to do about it — a filename over the 255-byte filesystem limit, a locked Personal Vault, deletions the safety net held back because earlier errors made the listing incomplete. A throughput timeout is separated out as its own cause rather than reported as a broken file, because it moves between runs and points at chunk size or concurrency, not at any one file. An error RedMan does not recognise is reported as unrecognised and shown verbatim; it is never guessed at, since a wrong explanation sends you after the wrong thing.
- [x] Added **chronic-versus-new** classification to that diagnosis, because a failure list that has read the same for weeks is a different problem from one that changed last night. Each run's failure pattern is fingerprinted and compared against the previous runs of the same job, so the report can say a cause is unchanged and for how long, surface a new cause hiding among familiar ones, and mark a cause that has stopped occurring as resolved. The history walk is bounded, so a job that has failed for a year cannot turn one page load into a table scan.
- [x] Added an **ntfy relay** so schedules on hosts that cannot reach RedMan can still report in. A machine outside the home network has no route inwards, which left its cron jobs and systemd timers permanently invisible — the one place where "no news" genuinely meant nothing was being watched. Those hosts now leave a signed one-line heartbeat on an ntfy topic and RedMan collects it on its own outbound polls, so no port is opened, no tunnel is added, and the direction of every connection stays exactly as it was. The line is signed rather than carrying a token, because anything published to a topic is readable by everyone subscribed to it: whoever can read the topic learns which schedules exist and whether they are passing, but cannot invent a result or alter one. Nor can they re-post a message they captured — de-duplication is keyed on the signature rather than on the message that delivered it, so a copied line cannot push a job's overdue deadline forward without forging anything. Collection is stateless and each poll re-reads an overlapping window, so a missed poll, a restart, or a slow message heals itself on the next round instead of leaving a permanent hole. The relay reports its own health on the status board, since a broker RedMan cannot reach would otherwise look identical to every relayed schedule failing at once.
- [x] Added a **status board** on the Status page that answers "is anything wrong right now" in one glance. Backup schedules, external job heartbeats, Docker containers, and peer connectivity are normalized into a single vocabulary and sorted worst-first, so the thing that needs you is always at the top. Containers now expose their healthcheck result as well as their state: a container that is running but failing its own healthcheck is reported as failing, which a plain reachability check would call fine.
- [x] Added a **Status** page with a durable event history. Notifications were previously fire-and-forget: ntfy delivered them, the browser channel showed them, and then they were gone. Every notifiable event is now recorded as it happens — independently of whether any delivery channel is switched on — so turning notifications off costs you delivery, not history. The page groups events by severity, filters by category and time window, and expands to the structured detail behind each one.
- [x] Added **External Jobs**, a single place to see whether schedules that RedMan does not run itself are still healthy. Host cron jobs, systemd timers, and container updaters on any machine report in with a one-line heartbeat, and RedMan compares each report against the schedule you declared for it. Because the check is time-based rather than message-based, a job that dies completely and sends nothing at all is exactly the case it catches — the gap in your monitoring that notifications can never close.
- [x] Added optional bi-directional pairing. When connecting to a peer you can now offer it backup space on your own instance in the same request, so a single accept sets up both directions instead of repeating the entire pairing from the other side. The offer travels inside the signed handshake transcript, the receiver decides whether to take it up, and the reverse API key is derived from the same shared secret under a separate label so it is never transmitted.
- [x] Added a copy button to the pairing identity fingerprint, so both operators can compare the exact string instead of retyping it from a screen. It falls back to a selection-based copy when the browser blocks the clipboard API, which is common on plain-HTTP LAN addresses.
- [x] Added the hardened full runtime with explicit local/proxy authentication, protected peer credentials, restricted backup accounts, exact-path Docker proxies, and schema 27 migrations.
- [x] Added a **DB Integrity** column to the SSD Backup run history and run report, so every run shows at a glance whether the database copy written to that destination passed its SQLite integrity check, was not due yet, or failed verification.

### Changed
- [x] Collapsed the per-job buttons on External Jobs into a single menu. Three controls sat on every card, two of them bare icons whose meaning had to be guessed or hovered for, and the destructive one looked exactly as ordinary as the others. The actions now carry words — *Pause watching*, *Rotate heartbeat token*, *Delete job* — so the row is quieter and each action says what it does. Closes on Escape or a click elsewhere, and Escape returns focus to the button that opened it.
- [x] Merged **External Jobs into the Status page** as tabs, because the status board already carried a card for them: the same health was counted twice, as five tiles on one page and a category on the other. The health banner sits above the tabs so "is anything wrong" is answered before a tab is chosen, and each tab carries the number of things wanting attention, since a tab you must open to discover a problem is a tab that hides it. The old address still works.
- [x] Changed status text to **say what happened instead of showing what was logged**. An exit code was printed raw, so *exit 1* asked the reader to know what the job meant by 1; codes with a defined meaning are now stated in words, per tool where the tool documents its own, and a code that means nothing in particular is said to mean nothing in particular rather than being given an invented explanation. A job's own message outranks its code. Detail views were a JSON dump and are now values, with bytes read as sizes and durations as time. Event bodies that were a table written as prose — five lines of *Label: value* stacked under a title — show those lines as values instead, leaving the sentence that actually says something.
- [x] Upgraded the bundled immich-go from v0.31.0 to v0.32.0, the first release that speaks the Immich V3 API. Against a V3 photo server the older build fails on every upload while parsing the response, and reports it as a malformed reply rather than as a version mismatch — so an import that had worked for months stops working the moment Immich is updated, and says nothing about why.
- [x] Made rotating an external job's heartbeat token ask first. The key button issued a new token on a single click, and because RedMan only stores the hash, that silently invalidated the token the host was still using — a monitoring page could take down the monitoring by being clicked on. Rotation now goes through the same confirmation as deletion, and the dialog says plainly that the current token stops working at once and that nothing installs the new one for you. The token screen itself now names the host it has to be installed on and states that the job is not reporting until it is, so the one thing the screen cannot do is no longer the one thing left unsaid.
- [x] Reworked accepting an incoming connection request. The slide-in notification now only asks whether you want to handle the request; the backup location, storage quota, and fingerprint confirmation moved to a centred dialog that opens when you accept. The dialog uses the standard form styling, browses for the backup location through the regular directory and share picker instead of a bare text field, and shows an example quota (1024 GB = 1 TB) plus a live readback of what the peer will get.
- [x] Ported the hardened application onto the clean v1.1.9 bridge baseline while retaining opt-in upgrade-readiness mode, its rollback workflow, and release checks.
- [x] Made Docker and Unraid the runtime resource-policy owners: deployment preserves existing UI-managed limits, writes reconstruction metadata, and RedMan adapts delta concurrency to effective cgroup memory, CPU, and PID ceilings.
- [x] Made the deployment host-observation window adaptive: it now early-exits once the container is stably healthy (a minimum floor plus consecutive clean samples) instead of always waiting the full fixed window, so healthy deploys promote in seconds while immediate failure detection is unchanged.

### Fixed
- [x] Fixed a running Media Import briefly falling back to **“Waiting for the first progress update”** whenever the page refreshed its active-run list. Rediscovery now updates run metadata without discarding hydrated progress. Online Takeout status also names both the current archive and phase, making the intentional Download → Import → Cleanup cycle visibly restart for each archive instead of looking like the overall job moved backwards.
- [x] Fixed an active Media Import card **forgetting its progress after navigating away and back**. A dedicated active-runs endpoint restores every running import independently of the selected 10-row history page, then resumes live polling, matching SSD, Hyper, and Cloud Backup behavior.
- [x] Fixed live SSD and Hyper Backup progress showing **0 checked / 0 transferred / 0 B** while rsync was already transferring. RedMan enabled rsync's human-readable output but only parsed raw numeric byte counts; progress lines such as `1.23G 42% ... (xfr#430, to-chk=11570/12000)` are now parsed into live bytes, percentage, and file counts.
- [x] Fixed guarded deployment treating **unrelated HDD-array D-state as proof that RedMan's SSD is unsafe**. Global D-state remains visible as a warning, but the deploy gate now performs bounded create, fsync, and cleanup probes on RedMan's persistent data path and Docker storage themselves. Active Time Machine I/O on the HDD array can no longer block an otherwise healthy SSD-contained rollout, while slow or unresponsive target filesystems still fail closed.
- [x] Fixed **Adding an online Takeout source appearing stuck after confirmation**. Source creation synchronously scanned every archive a second time before closing the dialog, even though the background import performs the same validated inventory before processing. Creation now persists the validated remote/path immediately and leaves archive enumeration to the tracked import run. The submit button also keeps a stable width while changing to *Adding…*, avoiding Safari's stale focus-paint artefact.
- [x] Fixed Google Photos Takeout discovery **remaining on “Detecting the Takeout folder…”** on a large Google Drive. Discovery recursively scanned every file on the remote and encountered unrelated ZIP archives before reaching the root `Takeout` folder; the regular JSON folder browser was also too slow against this provider. It now uses a fast root-only directory listing, recognizes `Takeout` or `Google Takeout`, scans archives only inside that folder, and times out instead of waiting indefinitely.
- [x] Fixed **Add Source staying disabled without an explanation** when Google Drive was selected but automatic Takeout discovery had not produced a folder. The dialog now shows discovery progress, highlights the missing requirement in warning amber, opens Advanced options after a failed detection, and directs the operator to Browse instead of leaving a grey button as the only signal.
- [x] Made path validation reject a NUL byte outright. `normalizePath` screened for shell metacharacters but let `\0` through, and every path in RedMan goes through it. Nothing was exploitable — the checks further down all failed closed on the truncated remainder — but that made the safety a property of what happened to come next rather than of the validator, which is exactly the kind of thing that stops being true when the code around it changes.
- [x] Fixed two schema assertions that had been failing since three migrations ago, and that nobody could see. Both tests hardcoded the expected version number, so each new migration silently broke them — and because `npm test` chains its steps with `&&`, the host-fixture step failing on a machine without a Docker socket meant the regression runner after it never ran at all. The expected version is now derived from the migration list itself, so it cannot go stale.
- [x] Fixed the regression suite skipping tests nobody noticed were skipped. The runner walked a hand-maintained list of filenames, so a test only ran if someone remembered to add it — two never had been. It now discovers every `test_*.mjs` on disk and runs all of them, with a short list of deliberate exclusions (the integration suite, the ones needing a live API, and those run by other npm scripts) that fails if it ever names a file that no longer exists. Also un-expired two delta tests: they pinned a fixture to a fixed date but only mocked the clock halfway through, so once real time moved more than a week past that date the code correctly started a new keyframe and the assertions began failing on their own.
- [x] Fixed displayed timestamps being off by the viewer's timezone offset. The peer list's *Seen 3h ago* and the time labels on the container metrics chart read the database value directly, and a value like `2026-08-01 03:03:41` carries no zone — so JavaScript read UTC as local time. A peer seen minutes ago could read as hours, and the chart's axis was labelled with times the samples were not taken at. Both now go through one shared parser that treats a bare database timestamp as UTC and leaves an already-zoned value alone.
- [x] Fixed every Hyper Backup job showing **Needs attention — Expected backup is overdue** immediately after it had succeeded. Run timestamps are written by SQLite in UTC, but were read back as `YYYY-MM-DD HH:MM:SS` without a zone, which JavaScript interprets as local time. Each completed run was therefore placed the host's offset earlier than it really was — behind that day's scheduled moment — so the schedule was judged still pending, and pending plus past reads as overdue. East of Greenwich every job was permanently marked overdue while the backups were in fact completing on time, which is the kind of warning that teaches you to ignore warnings. Timestamps from the database are now read as UTC.
- [x] Fixed backups failing indefinitely against a backup root that still holds content from before the restricted account existed. Such files are owned by root, and rsync mirrors the source's permissions — but changing a file's mode is refused to anyone except its owner, so every run ended with hundreds of *Operation not permitted* errors on files it could otherwise read and write. Nothing in the error pointed at ownership. The setup script now reports the situation with the command that resolves it, and `--adopt-backup-roots` hands the existing content over. Handing over is deliberately opt-in and never reaches the boot script: it is a one-off migration, not something to walk a multi-terabyte tree for on every start. Ownership is transferred with a single `chown -Rh`, which walks using directory file descriptors — passing paths to a separate process would let anything writing into the backup root swap a directory for a symlink between listing and change, and redirect a root-owned change outside the tree. Symlinks are re-owned without their targets, mount points and system paths are refused outright, and the whole step runs after the SSH configuration so a failure on one file cannot leave the account half-configured.
- [x] Fixed the restricted backup account being silently dismantled every time it was set up on Unraid. The setup script wrote the `Match` block, validated it, and then reloaded OpenSSH through `/etc/rc.d/rc.sshd restart` — which on Unraid rebuilds `sshd_config` from a template and takes the freshly written block with it. The script reported the account as ready while the host had in fact reverted to password authentication with no `AuthorizedKeysCommand`, so every backup to that peer failed and every deploy re-broke it. The reload now signals the running listener first, which re-reads the configuration in place without regenerating it, and the block is re-checked afterwards so a reload that discards it fails loudly instead of reporting success.
- [x] Fixed every Hyper Backup transfer to a restricted peer failing with *mkdir "…/cross-site/mnt/user/cross-site/…" failed: No such file or directory*. Hardening moved transfers onto a restricted account that reaches the filesystem through rrsync, which resolves every request underneath the allowed prefix — but jobs still sent the full absolute destination path they were created with, so the peer applied its own prefix a second time and wrote into a directory that cannot exist. The peer now advertises the path rsync must ask for, since it is the side that knows how its own account is confined. Because re-rooting only ever strips the peer's own prefix, the advertised path must be part of the destination the job was configured with — so a peer cannot name a different location and redirect the transfer, which on a pull would make `--delete-after` remove the local copy it was meant to restore. A peer that advertises nothing keeps the previous behaviour.
- [x] Fixed every Hyper Backup transfer failing with *Permission denied (publickey)* / *rsync: connection unexpectedly closed*. RedMan generates its own SSH key and deliberately stores it in the data volume so it survives container rebuilds, but the commands that actually connect never pointed at it — they relied on ssh finding a key in the default `~/.ssh` location, which is inside the container and therefore empty again after every recreate. Transfers kept working until the container was next rebuilt and then failed permanently, with the peer correctly holding the right key the whole time. The identity is now passed explicitly to both the rsync transport and the connection test, so the stored key is the one actually offered.
- [x] Fixed Hyper Backup refusing to run with *Storage usage unavailable: usage scan exceeded 5000 ms*. Measuring a backup target costs seconds and grows with the data, but the peer waited only five seconds and then killed the scan, so a destination slower than that could never be measured at all — every attempt paid the wait, none of them ever learned the answer, and the backup was refused over a failed measurement rather than a full disk. How long a request waits is now separate from how long the scan may run: the scan continues in the background and fills the cache, a figure that is merely old is served immediately while a refresh runs behind it, and a backup is only refused when a successful measurement actually shows the quota exceeded. A measurement that has not produced a figure yet is recorded in the peer audit log and allowed through. The scan budget is sized for a real backup target rather than a directory: the pair this was written for measures twenty seconds at one end and just under three minutes at the other, and a budget the scan cannot finish within is the same as never measuring at all.
- [x] Fixed Hyper Backup jobs failing with *Authentication failed — the API key was rejected by the remote peer* after re-pairing a destination. Each job stored its own snapshot of the peer's address and API key at creation time, while re-pairing derives a brand new ECDH key and can hand out a different address, so every existing job kept presenting a credential the peer had already replaced. Jobs are now bound to the peer's stable static identity and resolve the current address and key from the pairing record on every run, so re-pairing repairs existing jobs instead of silently breaking them — and a peer that moves to a new IP is followed automatically.
- [x] Fixed peer pairing failing with *Could not determine a private callback IP* on instances that run in a Docker bridge network. Auto-discovery already coped with that (it falls back to the Docker API), but pairing only looked at the container's own interfaces — which are exactly the `172.x` bridge addresses it must ignore — so the connection failed before any request left the host, even though `PEER_HOST` already declared a peer-reachable private IP. RedMan now resolves its callback address from the explicit Peer API URL, then `PEER_HOST`, then the host interfaces, validating the result as a private base URL before it is signed; the remaining failure message names both fixes instead of only the setting.
- [x] Fixed SSD backup runs finishing as *partial* with `Post-processing warning: database backup: SQLite integrity check timed out after 600000ms`. The database copy was written straight onto the backup destination and then integrity-checked there, so on a slow share or spinning array the full page-by-page read blew the 10-minute budget and the finished backup was deleted. RedMan now stages the copy beside the live database, verifies it on fast local storage, and only then copies the validated file to the destination.
- [x] Fixed run-file retention being unable to keep up with real backup volume: it removed at most 2.500 rows per six-hour cycle while active installs add far more per day, so `backup_run_files` grew without bound until the database became large enough to blow the integrity-check budget. Cycles now clear up to 25.000 rows and re-run after 15 minutes while a backlog remains, keeping the same 30-second time budget, 250 ms yields and per-cycle batch caps — failed cycles still fall back to the full six-hour interval.
- [x] Made snapshot conversion, pruning, file/database restore, Rclone destinations, legacy summary scans, Unraid capabilities, and deployment builds fail closed under interruption, unsafe paths, resource pressure, or validation errors.
- [x] Replaced raw immich-go crash dumps (including its full CLI usage/help text) in Media Import failure notifications and run history with a short, actionable summary; specifically recognizes an Immich API/schema mismatch (e.g. after an Immich upgrade changes a response field's type) and points at the fix, alongside distinct messages for auth and network failures.
- [x] Fixed three `deploy.sh` portability/robustness gaps found deploying to a second, non-root-SSH host: the existing-runtime-limits safety check no longer fails closed on Docker engines that render an unset `PidsLimit` as `<no value>` instead of `<nil>`; rollback-metadata and reconstruction-receipt capture now write through a privileged `mktemp`/`tee` instead of a plain shell redirect, so they succeed when the deploy SSH user isn't root (`sudo`-based targets); and the restart-policy-preservation step no longer copies forward `--restart no` from an abandoned, never-promoted canary left by a prior interrupted deploy attempt — it now falls back to `unless-stopped` instead of silently leaving the newly-promoted container without auto-restart.

### Security
- [x] Updated patched transitive build dependencies for bounded brace expansion, YAML parsing, ID generation, and source-map handling after new advisories appeared in the release audit.
- [x] Bounded startup migrations, credential conversion, database/pairing retention, private temporary cleanup, and per-run Immich retries; prevented incomplete retention cycles from resetting their cap every minute; moved large database integrity checks out of the API process, throttled automatic copies to once daily, constrained delta compression, and kept runs active through observable, cancellable post-processing; reconciled managed peer SSH grants fail closed at startup; scoped SSH identity strictly to RedMan app data; capped unauthenticated pairing payloads and storage; required private web/peer binding; rejected root SSH transfers at every runtime boundary; and added breakglass-hash-verified sequential deployment with restart-disabled canaries and host observation before promotion.
